# RETO 7 – Diagnóstico de riesgos

## 1. Introducción
En esta fase se han identificado algunos riesgos que pueden aparecer durante el desarrollo del proyecto TaskMaster. Para cada riesgo se analiza el factor que lo provoca, los posibles daños y las medidas de prevención recomendadas.

## 2. Fichas de riesgo

### Riesgo 1: No cumplir los plazos de entrega
- **Factor de riesgo:** mala planificación del trabajo o retrasos en la implementación de tareas.
- **Daños:** entrega incompleta del proyecto, pérdida de puntos o incumplimiento de requisitos.
- **Medida de prevención:** organizar el trabajo en fases, establecer un calendario y revisar avances periódicamente.
- **Módulo implicado:** Programación / Entornos de Desarrollo / IPE I

---

### Riesgo 2: Pérdida de información del proyecto
- **Factor de riesgo:** fallo del equipo, borrado accidental de archivos o ausencia de copias de seguridad.
- **Daños:** pérdida de código, documentación o pruebas desarrolladas.
- **Medida de prevención:** realizar copias de seguridad frecuentes, usar GitHub como sistema de control de versiones y subir cambios de forma habitual.
- **Módulo implicado:** Programación / Bases de datos / Entornos de Desarrollo / IPE I

---

### Riesgo 3: Uso inadecuado de equipos informáticos
- **Factor de riesgo:** cierre incorrecto de programas, instalación de software no autorizado o mal uso del entorno de desarrollo.
- **Daños:** errores en el proyecto, pérdida de trabajo o problemas técnicos en el entorno.
- **Medida de prevención:** seguir las normas de uso del aula, utilizar correctamente el software indicado y evitar instalar programas sin permiso.
- **Módulo implicado:** Entornos de Desarrollo / IPE I

---

### Riesgo 4: Errores en el código no detectados
- **Factor de riesgo:** falta de pruebas, validaciones insuficientes o revisión incompleta del sistema.
- **Daños:** fallos en la ejecución, datos incorrectos o funcionalidades que no funcionan como deberían.
- **Medida de prevención:** aplicar pruebas unitarias, revisar el código antes de entregarlo y corregir errores detectados durante el desarrollo.
- **Módulo implicado:** Programación / Entornos de Desarrollo

---

### Riesgo 5: Fallos al gestionar la información persistente
- **Factor de riesgo:** consultas mal planteadas, errores en el acceso a datos o falta de validación en operaciones sobre la base de datos.
- **Daños:** registros incorrectos, duplicados o pérdida de consistencia en la información.
- **Medida de prevención:** revisar las consultas, validar datos antes de guardarlos y aplicar buenas prácticas de acceso a datos.
- **Módulo implicado:** Bases de datos / Programación

## 3. Conclusión
El análisis de riesgos permite anticipar problemas que podrían afectar al desarrollo del proyecto. La prevención mediante planificación, copias de seguridad, validación de código y buenas prácticas de trabajo ayuda a minimizar su impacto y a mejorar la calidad final del proyecto.
